{% load i18n theme_tags cms_tags %}{% comment %} Site header of the `ride` theme (THM.6, THM.15 part 1, spec 14 §14.6): a dark Bootstrap navbar with the logo on the left, the main navigation, search and cart icons with text for screen readers, the help link and the language switcher. Navbar: a Bootstrap `navbar` WITHOUT `navbar-expand-lg`, which would switch at 62rem (992 px); the one switch point is 64rem (1024 px), set in 20-header-footer.css. From 64rem the navigation sits in the bar. Below it a menu button opens the Bootstrap offcanvas panel (`data-bs-*` only: focus is trapped inside, Escape closes it and returns focus to the button; no inline script or style). Without JavaScript (`no-js` class on , which ride.js removes) the burger is hidden and the panel is shown as a plain list of links below 64rem. Escape inside an open dropdown closes the dropdown first; a second Escape closes the panel (Bootstrap's behaviour). Sub-menus: a link with `children` (label and url each) gets a Bootstrap dropdown button next to it. The button carries `aria-expanded` and `aria-controls`; nothing opens on hover alone; Enter, Space or the arrow keys open it and Escape closes it. The vendored Bootstrap bundle (loaded with `defer` by the ride layout) does all of it, so base's Alpine components are not used here. Without JavaScript the sub-menus stay closed and the parent links remain; the sub-menu links are not reachable then. Search overlay (THM.15 part 2): the search icon is a link to the search page that Bootstrap turns into the trigger of a full-screen modal holding base's search form (same action, field and labels). Without JavaScript the link just leads to the search page. Focus moves to the field when the modal opens (`ride/js/mini-cart.js`); Escape closes it and focus returns to the icon. Close buttons (panels and search overlay): `btn-close--sprite` draws the X from the theme's same-origin sprite in currentColor; Bootstrap's own X is a data: URI, which the CSP (`img-src 'self'`) blocks. The `aria-label` names the button. Mini-cart (THM.15 part 2): the cart icon is a link to the cart page that opens an offcanvas on the end side. Its body is filled by HTMX from the small fragment `orders:cart_mini` (count and lines; no pricing quote, no flash messages) on load and after every add to cart. `#cart-count` is the polite live region with the item count in words; `#cart-badge` is the visual count; both are set by `ride/js/mini-cart.js` from `data-cart-count` of the loaded fragment. On the cart and checkout pages (app `orders`) the icon stays a plain link: their own markup would repeat the panel's ids. Secondary tools (THM.21): the help link, language switcher, garage menu and user tools live once, in `header_more.html`: in the menu panel (the drawer below 64rem, so the bar stays one row of logo, search, cart and menu button; the end of the inline navigation from 64rem), or beside the icons when the site has no menu. The staff-only "Site links" entry is added to `links` for staff only. Overlay (THM.21): when the page's first block is a hero (not a slider) the bar is transparent over it with a scrim gradient behind the links, and solid once the page is scrolled (`is-away` on , set by ride.js; without JavaScript the bar stays solid). CSS only decides it, from the header's next sibling. Context: `site_name`, `links` (label, url, optional children), `languages`, `search_url` and `cart_url` (default: the language home, where `?s=` is the CAT.27 search page, and `orders:cart`; an icon is left out without a url, never rendered as a dead link), and the context of the help link. {% endcomment %}{% with page_path=request.path|default:"" %}
